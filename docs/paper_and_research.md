# Automatic paper lifecycle and historical research

No orders are placed. New accepted 5m strategy signals automatically enter the durable paper ledger. Entry uses the next full bar after discovery, never the already-completed signal candle. Stops and targets are locked. Costs are assumptions; gaps through stops use the worse opening price. Same-bar stop and target is ambiguous. Missing data is not a loss or a win. GitHub bot-owned daily paged issues restore the ledger after runner-cache eviction. The website reads those issues automatically; history retrieval is limited to the latest 500 issues.

The daily research workflow requests 60 provider sessions of 15m history and one year of daily context. This is explicitly a degraded experimental 15m policy, not validation of the active 5m policy. Each prefix uses completed daily bars, causal confirmed pivots, and the same risk logic. Corporate-action resets use only actions effective by the simulated date. Provider history may be revised and is not point-in-time certified. Longer history is not fabricated. Current NIFTY membership creates survivorship bias; this is not a historical-constituent index backtest.

Offline one-step contextual Q research compares TAKE/SKIP using net-R outcomes. Duplicate records collapse before a chronological 70/30 split; holdout never trains the candidate. Minimum 100 training and 30 holdout closed trades are required. This is not deep RL and does not edit or promote production rules. Repeating the same dataset does not count as new evidence; a dataset fingerprint is reported. No eligible outcomes means INSUFFICIENT_DATA, not trained AI.

Market polling is scheduled, hourly health/outcome follow-up continues off-hours, and daily research runs separately. GitHub Actions can queue, delay, fail, or disable inactive schedules. This is not a guaranteed continuous process. Website availability does not prove feed readiness. Free keyless source completeness, native Pine parity and market-open rehearsal remain unresolved acceptance gates.
