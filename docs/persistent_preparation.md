# Persistent preparation, not unconditional trading readiness

Validated closed5m and completed daily bars are now retained in the existing SQLite cache across scheduled runner restarts. Later source omissions can reuse only bars actually observed previously; they cannot create timestamps or fabricate prices. Today's newly reported invalid bars remain invalid even if a cached observation exists. The most recent effective corporate-action reset filters cached history, preventing old-regime daily bars from bypassing daily warmup. History contains no credentials and is not added to public issues, source control or the public website. Existing runner-cache eviction remains possible; this is not guaranteed permanent storage.

Hourly runs now prepare history during market closures instead of returning before accessing the provider. Off-hours preparation never produces a fresh BUY/SELL or opens a paper position. Reports expose PREPARED/DATA_PENDING and counts of retained intraday/daily bars. PREPARED means context quantity and structural validation succeeded, not production certification, calendar acceptance, a signal or a guarantee of tomorrow's provider availability.

Free scheduled GitHub Actions are periodic executions, not a permanently running server. Vercel serves the website independently. Data outages, cache eviction, corporate actions, missing session candles and schedule delays can still block signals. A permanent READY label would conceal these conditions and is not implemented. Readiness can recover automatically when valid history becomes available.
